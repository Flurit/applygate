Stop coding agents from running terraform destroy in production.

applygate is a deterministic, local check that runs before an agent's tool call. It answers allow, ask or block, with a reason and a next step the agent can act on. It reads commands the way the shell does and reads plans the way Terraform does.

$brew install Flurit/tap/applygate

Pattern matching is not enough.

We replayed the same 17 dangerous and 13 harmless Terraform scenarios through each guard. A matcher reads text, not commands, and cannot see what a change will do.

Best existing open-source guard we tried, default config5 / 17
A competent hand-written Rego/regex policy14 / 17
applygate, protected tier17 / 17

The hand-written policy missed base64, variable and eval obfuscation, and blocked harmless text such as git commit -m "never run terraform destroy". applygate asked on 1 of the 13 harmless scenarios. The pack, the runner and the command to reproduce applygate's row are in the repository.

Two things a matcher cannot do.

No model is in the decision path. The same input always gets the same verdict, and every verdict says why.

Reads commands the way bash does

Parses with a real shell parser, follows cd, variables, loops and functions, and unwraps bash -c, eval, here-documents, sudo, xargs, find -exec, secrets runners, Makefile recipes and scripts. It decodes echo … | base64 -d | sh.

It tells commands from text: grep "terraform destroy" is a grep. What it cannot resolve statically, it refuses (ask) instead of guessing.

Judges the plan, not just the command

Maps the directory, workspace, backend and AWS profile to an environment tier, and flags a planfile made in another workspace, a backend changed since init, stale state and lock-file drift.

For apply <planfile> it reads the plan and flags destroyed or replaced stateful resources, removed deletion protection, internet exposure, IAM wildcards and changes to the state backend.

What it stops before it runs.

Verdicts depend on the environment's tier: protected environments block, standard ones ask, disposable ones mostly allow.

Destroys

destroy, apply -destroy, -replace, and plans that delete.

Unreviewed applies

apply -auto-approve with no saved plan.

State surgery

state rm/mv/push, force-unlock, -migrate-state.

Cloud CLI deletes

aws … delete-*, s3 rb, terminate, kubectl delete.

Hidden commands

eval "$(curl …)", curl … | bash, encoded payloads.

Guard tampering

Skip-permissions flags and edits to hook config, applygate's config or its log.

  • DeterministicRules decide, not a model.
  • LocalNo network calls by default. Telemetry is off unless you turn it on.
  • Fails closedA check that cannot finish blocks in protected tiers.
  • Observe firstLog what would be blocked for a few days, then enforce.

Running in a minute.

Start in observe mode: nothing is blocked while applygate learns your repository. Then review what it would have stopped and turn enforcement on.

$ brew install Flurit/tap/applygate
$ cd your-infra-repo
$ applygate init                # .applygate.yaml in observe mode; hooks Claude Code and Codex
$ applygate check "terraform -chdir=envs/prod destroy"
  # a few days later
$ applygate report              # what it would have blocked
$ applygate suggest             # a proposed config from the log; then set mode: enforce

Using Cursor, GitHub Copilot CLI, Gemini CLI, Windsurf, Devin, OpenCode or Cline? Each has an adapter, written from the host's own documentation and not yet tested live, so init leaves it to you: applygate hook install --agent cursor (or copilot, gemini, windsurf, devin, opencode, cline).
