- **What the round was briefed on:** merged main. The promise was not narrowed. The briefs listed the round-9 fixes and the newly enabled cross-directory rule and asked each reviewer for inputs of the same family that a rule still misses, and for ordinary work that now wrongly asks. Round-9 "Not done" items were declared known.
- **Severity was the same as rounds 7 to 9.**
- **The count fell from 17 to 12.** Round 9's rules held where they applied. The new criticals fall in four groups, and the first two are about the shell model rather than any one spelling:
  - **The analyzer follows something other than what the shell runs (7 criticals).** A bare shell's stdin (C1); `make -j TARGET` (C3); `>(bash)` and `xargs -0` (C4); function and alias shadowing through wrappers, `unset`, same-line aliases (C5); a docker image taken from a later word (C6); `${!x}`, `${x@P}`, `command printf -v` (C7); an unresolved `-chdir=$x` read as the working directory (C8).
  - **The cross-directory rule's own "followed" test (C2, and part of C6).** It is keyed by program name, and the backstop's "unrecognized wrapper" label counts as followed. Three reviewers found it independently: any unknown program with a standalone `terraform` word skips the rule.
  - **Strict shapes deny a spelling, not the family (C10 to C12).** `rg --hostname-bin`, `zip -T -TTPROG` glued, and `--` spellings of Go-style single-dash options run programs and are plain.
  - **State surgery through one more writer (C9).** `plan -out=<state file>` is claimed as state surgery in `docs/limits.md` and the changelog and is not implemented.
- **What held:**
  - The supply chain: `install.sh`, the Action, workflow pinning, goreleaser, the CI script against a hostile binary, the managed-install ownership checks (reviewer 5).
  - Failure handling: malformed hook input, pathological shell input (a 90-second fuzz run of about 400,000 executions without a crash), watchdog, corrupt trust store, a slow or hostile judge.
  - About 150 self-protection probes: guard-file writes by about 26 writers, PATH plants, renamed and patched binaries, nested-agent flags, the simulated managed install (reviewer 2).
  - About 120 documentation claims (reviewer 6), the config layering and trust rules, 30 hand-built plan-check shapes, the judge's answer parsing, cache and managed environment.

## Method

- **Same set-up as rounds 7 to 9:** a blind copy of main (`git archive`), review material and the attack pack removed; six reviewer agents, one area each, each in its own directory with a scratch `HOME` holding the fixture's trusted config; the same hard rules.
- **Verification flags:** **V** reproduced by the coordinator on main (`applygate check --no-judge` against a fresh copy of the fixture); **R** reproduced by the reviewer only (several ran the real program: bash 3.2, ripgrep 14.1.1, zip, Go, Terraform 1.14.6); **C** confirmed in the code by the reviewer. This machine has bash 3.2 only, so execution of `${x@P}` (bash 4.4+) rests on documented bash behaviour.
- **Disclosures:**
  - Reviewer 6 wrote one temporary file to `/tmp` and deleted it.
  - Reviewer 3 typed a stray `cat > /tmp/x` (an empty file, removed); a `make -n` on the same line sat in the stopped task and it could not confirm that it did not run.
  - The reviewers' Write tool refused `findings.md`; all six returned their reports as text.

## What this round says about the approach

- **The cross-directory rule is the right idea with one structural flaw (C2).** It asks wherever the analysis cannot follow code, but "followed" is decided by program name and the backstop labels guessed wrappers as followed. Fixing that one test closes the unknown-program family; the docker image bug (C6) and the backstop flags (R3-5) are two more cases of the same mistake, a program counted as taken apart when only a word was extracted.
- **The shell model keeps losing to bash semantics one construct at a time** (C1, C3, C4, C5, C7). A rule that covers the family: any construct whose bash semantics the analyzer does not implement exactly makes the command unresolved. The cost is more asks in protected directories, where strict shapes already asks for everything not plain.
- **Strict shapes by deny list keep losing to option spellings** (C10 to C12). The three criticals here are one defect: `hasOpt` matches the spelling it was given. An allow list per program (the options that cannot run code) closes the family; it costs asks for rarely used options.
- **The documentation claims a check that does not exist (C9).** `docs/limits.md` and the changelog list `plan -out=terraform.tfstate` as covered, and no test or scenario exercises it. A pack scenario for every claim in the "State" bullets would catch this kind of gap.
