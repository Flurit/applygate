**Release verdict: not releasable.** On the round-8 fix build (branch `fix/round-8`, f81c35a, PR #111: the round-8 criticals and highs fixed by rule), the round found 17 critical issues among 67 findings after merging duplicates (about 80 raw). The exit criterion is no critical finding.

- **What the round was briefed on:** the round-8 fixes (PR #111, not merged). The promise was not narrowed. The briefs listed the new rules (`>&`, `env` parsing, in-place editors, backend scans, install tracking, program variables, state surgery by glob and directory) and asked each reviewer for inputs of the same family the rules still miss, and for ordinary work they wrongly ask about. The cross-directory rule was documented as not enabled.
- **Severity was the same as rounds 7 and 8.** A destructive call allowed in a protected tier counts as critical, and so does one that runs in a protected directory while judged in a disposable one; so does state surgery allowed in a protected directory. High needs an unusual setup, or is a self-protection route without a managed install that the docs do not concede.
- **The count rose from 14 to 17.** Round 8's rules held where they applied. The new criticals are again the same three families one step further on, plus two structural defaults:
  - **The shell analyzer is a model of the shell, and it is still incomplete (8 criticals).** `set -a`, array subscripts and arithmetic that run `$(…)`, `mapfile -C`, unresolved words that expand to `-chdir=…`, glued `-eVAR=val`, Makefile `export`, `make -sC`, and a bare `env > FILE` whose redirect is dropped.
  - **Checks that skip a case or a file kind (5 criticals).** `terraform query` configuration, `init -backend-config`, a module added in the same command as `init`, a config file over 1 MiB, `graph -type=plan`.
  - **State surgery by a writer or a form not on a list (3 criticals).** `git checkout <rev>`, `tar -C DIR -xf`, an ancestor directory, `find`, a glob destination.
  - **Two structural defaults.** A tool name the hook does not know is allowed and not logged (R2-1); `git config --show-scope KEY VALUE` is read as a read (R4-1).
- **What held:**
  - About 150 self-protection probes by reviewer 2: ~30 alternate guard-file write routes, `env` parsing, the managed-install paths, self-tamper commands direct, renamed and modified, PATH plants. All blocked.
  - Every managed-install loosening route failed in the code reads (reviewers 2, 4, 5 and 6, with a Go test for the install files).
  - The judge's answer parsing, cache and managed environment; the MCP directory handling; telemetry; file permissions; `install.sh`, the Action inputs, workflow pinning.
  - About 7 MB hook inputs and a 90-case pathological shell corpus were bounded, except the stack overflow below.
  - About 195 of 230 documentation claims checked by reviewer 6 held.

## Method

- **Same set-up as rounds 7 and 8:** a blind copy of f81c35a with review material, the attack pack and finding IDs removed; six reviewer agents, one area each, each with a scratch `HOME` holding the fixture's trusted config; the same hard rules and severity scale.
- **A reboot interrupted the round.** The machine restarted while the reviewers ran and `/private/tmp` was wiped. The sandboxes were rebuilt at the same paths and the six agents were resumed with a note that their files were gone; each re-verified its findings on the fresh build.
- **Side effect:** reviewer 3 renamed the aws provider binary in the real `~/.terraform.d/plugin-cache` through a symlink for about a minute while setting up a test it then discarded; it put a script under the original name (never run), then restored the binary. Only the directory's modification time changed.
- **Verification flags:**
  - **V:** reproduced by the coordinator on the f81c35a build, with `applygate check` or the hook.
  - **R:** reproduced by the reviewer only; where noted the reviewer ran the real program (Terraform 1.14.6 with a harmless `credential_process` or provider writing a marker file; bash 3.2 and zsh 5 for shell semantics).
  - **C:** confirmed in the code.

## Medium findings (23)

- **R1-12.** A mounted production directory with an image whose name does not contain "terraform" (`--entrypoint terraform alpine`, `sh -c 'cd /w2; terraform destroy'`) is judged in the host directory.
- **R1-13.** `gsutil rsync -dr` (and `-rd`, `-ed`) and `aws s3 sync --del`/`--dele` (argparse abbreviations) ask in a protected directory instead of blocking.
- **R1-14.** `git archive --rem=../sub` and `git fetch file:x` slip the local-repository check (options and URL names matched exactly).
- **R1-15.** `sudo -D DIR` and `sudo --chdir=DIR` are not a directory change (needs a sudoers rule that allows it).
- **R1-16.** `yq -s`/`--split-exp` writes files named by the expression (guard files; from yq's docs); `terraform logout` and `-install-autocomplete` edit credentials and rc files unseen.
- **False positive.** `git commit -m "$(cat <<'EOF' … EOF)"`, the standard agent commit idiom, asks in protected directories.
- **R3-9.** `terragrunt run --all` ignores units that use `terragrunt.hcl.json` (a single unit is read).
- **R3-11.** The name-hint separators (`/_.:-`) miss `@`, space, `+`, `=`, `,`, `~`: `AWS_PROFILE='alice@prod'`, `TF_WORKSPACE='team@prod'`, `admin@prod.us-east-1.eksctl.io`, `'Acme Production'`.
- **R3-12.** `plan-check` resolves the tier from fewer signals than the hook: a local backend `path` into another environment is ignored (`policy.DirSignals` omits `StateDirs`, `WorkspaceUnknown`, `SourceDirs`); the CI gate allows what the hook blocks.
- **R3-13.** `terragrunt exec -- terraform destroy …` and `terragrunt backend delete|bootstrap|migrate` are never classified as destroy or state work (ALLOW in standard; ASK, not BLOCK, in protected).
- **R3-14.** Exposure rules miss real attribute shapes: legacy `acl = "public-read"` on `aws_s3_bucket` and objects, `aws_mq_broker`, `aws_rds_cluster` `publicly_accessible`, `aws_eks_cluster` `public_access_cidrs`, MSK, network ACLs, glacier and log resource policies, SSM document sharing, ports 2375, 5985, 10250, 2049, `prefix_list_id` rules.
- **R4-5.** An oversize command (over 16,000 bytes), an oversize write (over 4,000 characters) or a redaction-hidden program is an allow in a disposable directory even when it names production.
- **R4-6.** The judge is given only the directory's tier; profile, workspace, project and kube-context signals the config maps to prod are ignored (`hook/judge.go` `judgeInput`).
- **R4-7.** `applygate check` reaches the judge for an agent that gives it a pty (`script`, `python3 pty.spawn`, `expect`).
- **R4-9.** In-tree `cp`, `mv`, `ln`, `tar x`, `unzip`, `git apply`, `git am`, `sed -Ei`, `yq -i`, `git --output`, `format-patch -o`, `find -fprint`, `tree -o`, `sort -o` from an unjudged `/tmp` file bypass the judging of file writes.
- **R4-11.** The filter's secret-file patterns miss `/proc/*/environ`, `service-account.json`, `kubeconfig-*`, `.git/config`, `*.tfplan`, many credential dotfiles.
- **R4-12.** Generic MCP shell tools are recognised by exact name only (`run_script`, `bash_exec`, `execute_python`, `terminal_run` pass).
- **R5-2.** The `lockfile-drift` finding is lost when `.terraform.lock.hcl` or a `.tf` file is over 1 MiB.
- **R5-3.** A chain of 400,000 `&&`/`||`/`|` or a 2 MB `$((1+…))` overflows the Go stack (fatal, exit 2, not recovered, not logged); about 700 times memory amplification (1.3 to 1.65 GB RSS before the size check). - **R5-4.** The decision log writes `ActionResult.Backend` (an http backend URL with credentials), `Workspace`, `Profile`, `Dir`, `Cwd`, `Paths` unredacted; `Redact` misses `$`-leading values, `*_KEY` names, `--key`, `sqlcmd -P`, `npm config set …:_authToken abc`, `docker login --password-stdin`, escaped quotes.
- **R5-5.** The CI action puts plan text (a `for_each` key with backticks and newlines) into the job summary and the `summary` output unescaped: markdown injection, and script injection for a workflow that interpolates the output into `run:`.
- **R6-7.** "Reads cloud credential files" is claimed as defended in threat-model.md but is an ask on a few names; globs, `cd`, `<`, `grep -r`, `jq`, `kubectl config view --raw`, `~/.kube/config`, `~/.ssh/id_rsa` pass; credentials.md says reads are not blocked.
- **R6-8.** `git config` of an unknown key, or of `branch.*.remote|merge`, is a block in every tier; policy.md says ask and lists `branch.*` as safe.

## What the criticals have in common

- **The shell analyzer is an incomplete model of the shell (R1-1, R1-2, R1-4, R1-5, R1-7, R6-1, R6-3).** Round 8's rules made unresolved *variables* unknown. These are unresolved *words* in command position, shell options that change which assignments are exported, arithmetic contexts, builtin callbacks, glued option values and a redirect on a command with no program. Each is a place where the shell evaluates something the analyzer does not follow. The rule that would cover the family: a construct the analyzer recognises as evaluating or expanding something it did not resolve makes the call unbounded, in every tier.
- **A scan skips a file kind or a source of configuration (R3-1, R3-2, R3-3, R5-1, R6-2).** The program scan reads `.tf` files; Terraform also reads `*.tfquery.hcl`, `-backend-config`, modules `init` fetches, and files over the cap. The rule: whatever the scan cannot read or has not read is unknown, and unknown asks; and the list of subcommands that start providers comes from running Terraform, not from the docs (R6-2 shows the doc list was wrong).
- **State surgery by a writer or form not on a list (R1-6, R6-4, R6-5).** The same family as round 8. The rule: a write whose target cannot be shown to avoid a state file in the tree under the directory is state surgery; the check should be on the effective target of `tar -C`, `checkout <rev>` and ancestor directories, not a list of verbs.
- **Two structural defaults (R2-1, R4-1).** A tool name the hook does not know is allowed; a flag the parser calls a read is allowed. Both are default-allow where default-ask is the rule everywhere else.

## Recommendation

- **Fix all 17 criticals and the 15 highs by rule**, as in round 8, and measure the cost on the agent trial first for the shell rule ("an unfollowed expansion is unbounded") and for the file-kind rule.
- **Decide the cross-directory rule.** R6-6 shows that without it the protection holds only for what the analyzer follows or when the agent works in the protected directory. Round 8 measured it at +30 asks of 162 in dev and staging. Most of the shell-analyzer criticals this round (R1-1, R1-2, R1-4, R1-5, R1-7, R6-3) are ALLOW only from a disposable or standard directory or are ASK-not-BLOCK in a protected one: a command the analyzer cannot follow is not judged at the most protected tier under the root, which is what the rule does. It has not been re-measured on this build; It is the user's call.
- **R2-1 and R4-1 first:** they are one rule each and the cheapest fixes (scan every unknown tool's arguments for commands and paths, as `MCPGuardPath` does; `read` only for an actual get or list action).
- **The credential boundary (docs/credentials.md) matters more each round.** Most criticals reach a destroy or an arbitrary program through a plain-looking command; read-only agent credentials and MFA for writes keep that harmless whatever the hook decides.
- Round 8's mediums and lows are still open (zsh glob qualifiers, `functions[x]=`, `add-zsh-hook`, the apply race), and so are this round's.
