# Fix plan for the v0.6.0 pre-release review (2026-11-02)

This plans a fix for every finding in [the review](2026-11-02-pre-release-review.md): 80 findings, cited by ID (A1, C7 …).
- **Order:** the fixes are grouped into workstreams, which ship as pull requests in five milestones.
- **The gate:** a fresh red-team round against the fixed build has to pass before anything is released.

## Principles

Every workstream applies the same four rules, which reverse the root causes in the review:

1. **Unknown means unresolved, never allowed.** A tool, program, option or shell construct applygate cannot model exactly is judged as unresolved. An unresolved command is judged at the most protected tier the command could reach, as unknown directories already are.
2. **Judge identity and effect, not names and text.** Paths are compared after resolving symlinks and case. Programs are identified by what they are (same file as applygate, an engine by case-folded name) and by what they do to a guard path (write, move, remove, extract), not by their spelling.
3. **Nothing the agent can see or produce counts as a person.** A terminal, a word shown in a block message, or a file the agent's user can write is not proof that a person is there.
4. **Judge what will run, not what is on disk now.** Anything the same command writes before it runs is unresolved.

## Milestone 0: make every finding a failing test (first PR)

Before fixing anything, turn each reproduction in the review into a test that fails today. Each later PR then proves its fix and cannot regress.

- **A new pack, `harness/pack/attack/`:** one scenario per bypass in groups A to E, roughly 120 scenarios. Each records the command or hook payload, the directory and tier, the expected verdict, and the finding ID. The pack is replayed in the Claude and Codex formats.
- **Go tests:** cover what the pack cannot express.
  - **Approvals:** key binding of content and args; the lock timeout.
  - **Config:** layered configs, tighten-only fields, per-action resolution.
  - **Plan gate:** planfiles written in the same command; instance keys; unknown values.
  - **Judge:** cache, filter shapes, error and oversize handling.
  - **MCP:** truthiness; carrying the cluster.
  - **Redaction:** the missing secret forms.
- **New unit tests for `internal/classify`,** which has none.
- **CI:** add `run.py --format codex` (J9) and the attack pack. Mark the attack pack as expected to fail until milestone 1, with a per-scenario allowlist that shrinks as fixes land, so CI shows progress without being red.

**Size:** M. **Done when:** every finding with a reproduction has a test, and the failing list equals the review.

## Milestone 1: self-protection (the release blocker)

Until this is fixed, an agent can switch off every other protection.

### Workstream 1: a guard engine based on canonical paths

Covers A2, A3, A6, A8, A9, A10, B2, C11 (symlink part) and D4 (shared helper).

- **A new package, `internal/guard`, with three functions:**
  - **`Canonical(path, cwd)`:** absolute and clean, with `EvalSymlinks` on the longest existing prefix, then case-folded on darwin and windows. For a path that does not exist yet, the canonical parent is joined with the case-folded name.
  - **`Set`:** the guard paths, resolved once per run.
    - **Applygate's own files:** the user config, its directory and the legacy path; the default log and the configured log; `approvals.json` and its `.lock`; `judge-cache.json`; `telemetry.json`.
    - **The binaries:** `os.Executable()` and its directory's `applygate`.
    - **The plugin's directories.**
    - **The host settings files,** including those under `$CLAUDE_CONFIG_DIR` and `$CODEX_HOME`.
    - **The existing glob patterns.**
  - **`Touches(target)`:** true when the canonical target is a guard path, lies inside a guarded directory, or is an ancestor of either. Removing or renaming `~/.claude` touches `~/.claude/settings.json`.
- **Effect-based classification in `internal/classify`.** Every program that writes, moves, removes, links or extracts gets its target arguments put through `Touches`. That includes directory targets (`cp f DIR/`, `-t DIR`) and extraction roots (`tar -C`, `unzip -d`). The list of writers grows to cover:
  - `curl -o/-O`, `wget -O`, `ditto`, `patch`, `cpio`, `rsync`;
  - `git mv`, `git checkout|restore|reset|stash -- <path>`, `git apply`;
  - `find -delete`, `xargs` with a remover, `sponge`, editors (`vi`, `vim`, `nano`, `ed`, `emacs`), and `apply_patch` run from the shell (B2).
- **Interpreter bodies and unknown programs.** For any body passed to an interpreter (Python, Node, Perl, Ruby, awk and the rest of C7's list), search for every guard path and every ancestor of one, in canonical, `~` and `$HOME` forms, whether or not the body mentions a tool. A match is guard tampering. An unknown program given a guard path or an ancestor as an argument is an ask in standard tiers and a block in protected ones.
- **Tests:** the attack-pack scenarios for A2, A3, A6, A9 and A10. Also: guard paths with each XDG variable and `CLAUDE_CONFIG_DIR` set; case variants on darwin; a symlinked parent.
- **Size:** L.

### Workstream 2: commands that turn applygate or the hook off

Covers A5, A7 and A11.

- **Identity, not names.** A program counts as applygate when either:
  - its case-folded base name is `applygate` or `seatbelt`, or
  - it resolves (through `PATH` lookup, `which` or an absolute path) to the same file, by inode and device, as `os.Executable()` or a recorded hook binary.

  When the program cannot be resolved, it counts as applygate if its arguments match an applygate tampering subcommand.
- **Tampering subcommands, in every tier:** `approve`, `apply`, `hook install|remove|uninstall`, `init`, `disable`, `telemetry on|off`. `hook install` is new to this list.
- **Agent CLIs:**
  - **Claude:** `claude plugin disable|uninstall|remove`, `claude config set` (any hooks or permissions key), and `--settings` / `--setting-sources` / `--dangerously-skip-permissions` on a nested `claude`.
  - **Codex:** `codex -c` or `--config` touching hooks or sandbox, `CODEX_HOME=` on a nested `codex`, and the equivalents for the other hosts we install into.
- **Remove the `seatbelt` shim** from the release archive and `install.sh`. `doctor` keeps recognizing old `seatbelt hook` entries and tells the user to run `applygate hook install`.
- **Size:** M.

### Workstream 3: approvals

Covers A4, A12, A14 and A15. It depends on D-1; this is what option (a) means.

- **Approvals off by default.** On a host that cannot prompt, an ask stays a block, and the message explains how to allow the command: run it yourself, or turn on approvals in the user config once an OS presence check exists.
- **When turned on, approvals need the OS presence check.**
  - **macOS:** a Keychain item whose access control requires the user's password or Touch ID, read with `security`, which shows the system dialog.
  - **Linux:** `pkexec` or a `sudo -v` prompt.
  - **Elsewhere:** approvals cannot be turned on.

  This step can come after the release. The rest of the workstream cannot.
- **The approval key** gains a sha256 of `Content` and of the full `Args`, not the 4 KB command copy (A12). `Approve` takes the full key that it displayed and fails if that record changed (A15).
- **The prompt** escapes control characters and shows the unredacted command parsed into words (A15).
- **The lock** becomes non-blocking with bounded retries, and runs inside the deadline. A lock failure keeps the decision (A14).
- **Size:** M now; M later for the presence check.

### Workstream 4: `applygate apply`

Covers A1.

- **`--plan-json`** moves behind the `testhooks` build tag. The release build does not have it, and the hook judges any `--plan-json` as tampering.
- **`--yes`** is removed. CI uses `applygate plan-check` followed by `terraform apply`.
- **In the hook,** `applygate apply <planfile>` is judged exactly as `terraform apply <planfile>` is, and with workstream 2 it is tampering when an agent runs it. Its terminal confirmation is kept for people at their own terminal.
- **Size:** S.

### Workstream 5: tools the hook never sees

Covers B1, B3, B4 and B5.

- **Matcher and doctor.** `hook install` writes the Claude matcher `*`. The plugin's `hooks.json` matches the same. `doctor` warns about an older matcher, and checks that the hook entry has `onFailure: block`.
- **Treat any tool carrying a command as a shell call.** In every adapter, a tool not on the known list whose input has a string `command`, `cmd`, `script` or `code` field is judged as a shell call. That covers `Monitor`, `PowerShell` and future tools. Other unknown tools are allowed as before.
- **An unreadable command is an error.** A shell tool whose command cannot be read is an error under `on_error` for Claude and Codex too (B3).
- **Typed decoding only for native tools.** MCP inputs keep their raw JSON (B4).
- **Text typed into a running process is judged as a command:** `tmux send-keys`, `screen -X stuff`, `expect send`, and Codex `write_stdin`. Codex `write_stdin` needs a live check that the hook fires for it (B5).
- **Size:** M.

### Workstream 6: configuration trust

Covers D1, D2, D3 and E1's `.terraform` part, under decision D-2 (a).

- **Layered loading.** Load the user config, then every `.applygate.yaml` from the repository root (the git top level, or the outermost config) down to the action's directory.
- **One rule per field,** in one table in `config.go`. Every field is labelled:
  - `user-only`: log path, live checks, judge, approvals, aliases, `unknown_dir`, and with D-2 (a) also `mode`, `on_error`, `strict`, `default_tier`, `name_hints`, `max_destroy`, `run_show`, the preflight switches and `protected_paths` removal;
  - `tighten-only`: tiers, environments, guard paths and `protected_resources` can only add protection;
  - or `any layer`.

  A test asserts that every field of `Config` has a label.
- **Per-action resolution.** The config and tier are resolved for each action's canonical directory, not for the event's working directory. When an action's directory has its own config chain, the stricter result wins (D3). `**` globs are anchored to the directory of the config that declares them.
- **Reject YAML merge keys** in repository configs (D2).
- **Migration note.** Teams running observe mode through the repository config move it to the user config. `doctor` reports a repository config that sets a user-only field, and says it is ignored.
- **Size:** L.

### Workstream 7a: the plan written in the same command

Covers E1.

- A command that writes the planfile before applying it gets a critical `plan-unverifiable` finding, which is a block in protected tiers and an ask in standard ones. The writes that count are `plan -out`, a redirect, `cp`, `mv`, `ln` or `tar`, and anything targeting `.terraform/`, `TF_DATA_DIR` or `.terraform/environment`.
- The same applies to workspace and backend files written earlier in the command.
- **Size:** S. It shares the "written earlier in this command" tracker with workstream 8 (C11).

**Milestone 1 is done when:**
- every A, B, D1 to D3 and E1 scenario in the attack pack passes in both formats;
- the existing pack still passes;
- the agent-trial replay shows no new false positives in disposable and standard tiers.

## Milestone 2: the shell analyzer, under "exact or unresolved"

### Workstream 8: analyzer fixes

Covers C1 to C14 and H1, with D-3 (a).

- **Names:** case-fold program names before every engine, wrapper and interpreter lookup (C1).
- **Words:** any word the analyzer cannot reproduce exactly is unresolved (C2). That includes unquoted `*?[`, a leading `=` (zsh), `$'…'` with `\u`, `\U` or `\c`, `echo` with escapes, and `printf` with `--`. Also implement `echo -e`'s `\0NNN`.
- **State:**
  - background statements (`&`) run on a cloned state;
  - function bodies run on the caller's state, with the recursion guard kept;
  - `popd` and `dirs` use a directory stack, or make the directory unknown (C3);
  - the variables written by `read`, `printf -v`, `mapfile`/`readarray`, `getopts` and `declare -n`/`local -n` become unresolved (C5).
- **Coverage:**
  - walk case words and patterns, declaration arguments, and C-style loop headers (C4);
  - treat `trap ARG …` as `eval ARG`;
  - add a backstop that walks substitutions in any node type the analyzer does not handle explicitly.
- **Placeholders:** `xargs -I/-i/-J` and `parallel` templates become unresolved words, or use the known stdin. `parallel` with no template is `stdin | sh` (C6).
- **Interpreters:** parse options per language (bundled short flags ending in `c`/`e`, `--eval`, `-p`, `-E`, skipping options before the script path). Add awk, gawk, lua, tclsh, Rscript and julia. When no code argument is found, search all arguments (C7).
- **Programs that run commands through their own options (C8):**
  - git: `-c alias.*=!`, `core.pager`/`sshCommand`/`fsmonitor`, `bisect run`, `rebase -x/--exec`, `submodule foreach`;
  - `ssh -o ProxyCommand/LocalCommand`, `flock … -c`, `su`/`runuser -c`, `fish`/`csh`/`tcsh -c`, `conda`/`mamba run`, `nix run|shell --command`;
  - the attached forms of `env -S`.

  A `notWrappers` entry no longer suppresses the backstop for these subcommands.
- **Terragrunt and `-chdir`:** honour `--working-dir`, `--terragrunt-working-dir`, `TG_WORKING_DIR` and `TERRAGRUNT_WORKING_DIR` anywhere in the arguments. An unresolved `-chdir` makes the directory unknown (C9).
- **make:** treat `-p` as executing; under `-n`/`-q`/`-t`, still analyze `+` and `$(MAKE)` lines; parse `--directory=`, `--file=`, `--makefile=` and `-fX`; treat `MAKEFILES` and `MAKEFLAGS` as unresolved (C10).
- **Written in this command:** a tracker records the paths written by redirects, writers, `ln` and `mkdir` earlier in the same analysis. Reading, sourcing, running or `cd`-ing into one later is unresolved (C11). Workstream 7a uses the same tracker.
- **Failure:** parse errors, an exhausted budget and work limits are judged at the most protected tier under the root, and so is a recovered panic (C12, H1).
- **Aliases:** re-parse alias text with the shell parser, and keep self-referential aliases (C13).
- **Cloud CLIs (C14):**
  - read words only in verb positions, and never let a read word override a write;
  - `delete-*`, `rm` and `remove` are destructive;
  - skip `--flag value` pairs generically, using the known boolean flags;
  - fold `TF_CLI_ARGS` and `TF_CLI_ARGS_<sub>` into the arguments;
  - classify `gsutil`, and `kubectl --cluster/--server` and `helm --kube-apiserver` as target flags.
- **Size:** XL. It splits into about six PRs by bullet group, each turning its attack scenarios green.

### Workstream 9: measure a strict mode

This is the experiment D-3 asks for.

- **Prototype:** a `strict_shapes` setting, in which protected tiers allow only commands whose every word resolved and whose structure is a plain pipeline or list of known programs. Everything else is asked about.
- **Measure** benign asks on the agent-trial log (162 calls) and the OSS-corpus traffic, against the attacks closed beyond workstream 8.
- **Decide** with the numbers.
- **Size:** M.

## Milestone 3: tier resolution and the plan gate

### Workstream 10

Covers D4 to D8 and E2 to E5.

- **D4:** use `guard.Canonical` for tier path matching. A symlink alias and its target resolving to different tiers takes the stricter.
- **D5:** honour `TF_DATA_DIR` in `InitBackend`, `StaleState` and `BackendChanged`. An unresolvable `TF_DATA_DIR` means an unknown backend, judged as protected.
- **D6:** in backend patterns `*` matches across `/`. Document it.
- **D7:** `suggest` escapes control characters in every logged value it writes. `Check` rejects a proposal containing a key the generator did not emit.
- **D8:** read `--kubeconfig` (kubectl, helm) and `--configuration` (gcloud) from the command line.
- **E2:** never run `terragrunt show`. Run `terraform show` in the Terragrunt cache directory instead. Before any `show`, verify `.terraform/providers` against the hashes in `.terraform.lock.hcl` as git HEAD has it. If that fails, the finding is `plan-unreadable` (critical). Document the remaining risk.
- **E3:** replacing a resource is judged like deleting it.
- **E4:** strip instance keys before matching `protected_resources`, on both module and resource parts.
- **E5:** an unknown value of a watched attribute is a high finding.
- **Size:** L.

## Milestone 4: judge, MCP, secrets, failure handling

### Workstream 11: the judge

Covers A13 and F1 to F4, F7, F8, F10 and F12.

- **Cache:** store only escalations, key on the full command argv or endpoint and model, ignore entries dated in the future, and give `check` its own cache (A13).
- **Filter:**
  - allow argument shapes, not program names, with flags known safe for git, tar, sort, zip, rg and go;
  - remove `mvn`, `gradle`, `dotnet` and `npm init`;
  - expand clustered short flags before the push check (F1);
  - send shell file writes to the judge with the written text (F2);
  - resolve `outside()` against each invocation's directory (F3);
  - add credential patterns: `*.tfstate*`, `*.tfvars`, `.vault-token`, `.my.cnf`, `.s3cfg`, `.boto` and CLI config directories (F7).
- **Limits:** cap the command and arguments sent to the judge, as content is capped. In protected and standard tiers, oversized input, a refusal or an unreadable answer is an ask. A network error or timeout still leaves the rule decision. Decode the last valid JSON object in an answer (F4).
- **Content and the deadline:** add the Copilot, OpenCode and Cline edit fields to `WriteContent` (F8). Run `claude-cli.sh` from a temporary directory with setting sources restricted (F10). Bound the judge by the time remaining, minus the WaitDelay, minus a 2 s margin, and correct the docs (F12).
- **Size:** M.

### Workstream 12: MCP

Covers F5, F6, F9 and F11.

- **Truthiness (F5):** any present value other than a falsy one is true. A `params` that is not an object is unresolved.
- **Clusters (F6):** carry `cluster_name`, `project_id` and `location` into the translated command. A named cluster that cannot be mapped is judged at the most protected tier. Translate `flags`.
- **Program mismatch (F9):** for a server that requires a given program, a translation whose first word is another program is unresolved.
- **Process input and operators (F11):** input to a non-shell process is unresolved, and so are bare operator tokens in argv.
- **Size:** S.

### Workstream 13: secrets and failure handling

Covers G1, G2 and H2.

- **Redaction (G1):**
  - run the PEM pattern first;
  - add space-separated values after secret-named flags and keys, `-pPASS`, `-u user:pass` and URL userinfo;
  - add the token prefixes `github_pat_`, `glpat-`, `sk-`, `sk_live_` and `AIza`;
  - stop values at `;`, `|` and `$`;
  - redact `Via`.
- **Telemetry (G2):** map `version`, `agent` and `mode` to known enums and a semver pattern, and drop anything else.
- **Failure handling (H2):**
  - one function decides how failure is enforced, used by `fail`, timeout, panic and `Settle`;
  - approvals, the judge and the log run inside one deadline budget;
  - telemetry gets whatever time is left, or none.
- **Size:** M.

## Exit criteria for the release

1. **Tests:** every finding is fixed, or listed in `limits.md` as a known gap with a reason. Each has a test.
2. **Packs:** the attack pack passes in the Claude and Codex formats, and the existing pack and selftest pass.
3. **False positives:** the agent-trial and OSS-corpus replays show benign asks no worse than v0.5.0 in disposable and standard tiers. Any increase in protected tiers is measured and written down.
4. **A second red-team round.** Run it against the fixed build, with six new reviewers who have not seen this review or the fixes, briefed the same way. Release only when it finds no critical issue. A high issue found in that round is fixed or documented.
5. **Live checks:** Claude Code and Codex are re-run live (the hook, an approval if turned on, the matcher), and the results are recorded in `review/`.

## Order and parallelism

```
M0 attack pack ──► M1: WS1 guard ─► WS2 tamper ─┐
                       WS4 apply (independent)  ├─► WS6 config ─► WS7a plan ─► M1 exit
                       WS5 tools (independent)  │
                       WS3 approvals (D-1) ─────┘
                 M2: WS8 analyzer (6 PRs, parallel after WS1) ─► WS9 measure
                 M3: WS10 (after WS1 and WS6)
                 M4: WS11, WS12, WS13 (independent of each other)
                 M5: WS14, WS15 (WS15 last) ─► red-team round 2 ─► release
```

- **What can run side by side:** workstreams 4, 5, 12 and 14 are independent and can run alongside others.
- **The ordering constraints:** workstream 1 comes before 2, 6, 8 and 10, because they share `guard.Canonical`. Workstream 15 is last.
